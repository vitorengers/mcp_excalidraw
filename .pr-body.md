Closes #324

## What was wrong

A fresh clone that runs `npm ci && npm run build && node dist/server.js` gets a **blank
Excalidraw canvas** — no tabs, no cards, no blocks — and nothing said why. The board on screen is
`default`, which has no project behind it, so the `docs/board.excalidraw` that the tracked
`board.config.json` names is never read: that field is only ever looked at for a *registered*
workspace. `docs/running.md` treated the registry as one optional-looking row in the variable
table, and the only worked example in the repository (`docs/workspaces.md`) pointed at the
maintainer's own directories.

## What the issue's other half turned out to be

The issue also asks that documentation cards answer 200 rather than the `no-docs-dir` 404.
**That half already landed**, in #313: `EXCALIDRAW_DOCS_DIR` unset now resolves to the build's own
`docs/` (`src/server.ts`, `TOOL_DOCS_DIR`) instead of switching the route off, so a card answers on
a canvas with no project at all. The check asserts it anyway — it is a line in the definition of
done, and a fallback nothing holds is a fallback that can be removed by accident.

## The decision: the documentation version, not the behavioural one

The issue offers two ways to satisfy the same outcome, and explicitly leaves the choice open.
This takes the documented procedure rather than auto-registering the working directory, for one
concrete reason beyond size: **every check in this repository spawns its canvas with
`cwd = repoRoot`**, and this repository has a `board.config.json`. A server that registered its
own working directory when the registry was empty would quietly write this project into ~150
throwaway registries and change what those checks assert — including the ones whose whole subject
is a board with nothing configured. A startup that mutates a user's registry as a side effect is
also a surprising thing for `node dist/server.js` to do.

The check asserts the *outcome* and not the mechanism, as the issue's Risk section asks, so a
later zero-config path can shorten the section without invalidating it: it parses whatever the
first-run section says and follows that.

## The change

- **`docs/running.md`** gains `## The first run: register the clone as its own project`,
  immediately after the short version: three numbered steps — write a one-entry registry, point
  `EXCALIDRAW_WORKSPACES` at it, open the board. It also says what the `+` in the tab strip does
  and does not do: it registers a project immediately, but board files are read at startup, so a
  tab added that way stays empty until a restart. That was verified against a running server, not
  read off the code.
- **`README.md`**'s run section links the new heading and states the symptom in one sentence, so
  a reader who has just seen the blank canvas finds the procedure from where they started.

## The check

`scripts/check-first-run-board.mjs` — `Tier: fast`, self-contained, its own server on a port the
kernel handed out, no browser, nothing that talks to GitHub. It is the reader following the
document rather than a paraphrase of it:

- finds the section by its heading, and requires `README.md` to link that heading's anchor;
- reads the **setting name** out of the section and starts the server with that and nothing else;
- reads the **registry JSON** out of the section's own fenced block and writes it verbatim, with
  the one `path` swapped for a throwaway copy of every tracked file (a clone with no `.git`);
- asserts the canvas holds every non-deleted element of that copy's `docs/board.excalidraw`, and
  that `GET /api/docs/running` answers 200 with the copy's own markdown.

A section rewritten to name a different variable or show a different registry is therefore
followed, not failed — and a section describing a procedure that does not actually produce a
board fails, which is the failure mode prose alone cannot have.

**Run against the tree as it was**, it exits 1 on the first case:

```
1. docs/running.md tells a fresh clone what to do first
  FAIL  docs/running.md has no "## The first run…" section — a fresh clone is still on its own
```

## Verified

`tsc`, `vite build`, `node scripts/check-first-run-board.mjs`, `node scripts/check-board-map.mjs`,
`check-english-only`, `check-tiers`, `check-docs-index`, `check-docs-counts`, and the full
`npm test`.

## Noted, not folded in

Adding a project through the `+` leaves its tab empty until the server is restarted —
`POST /api/workspaces` reloads the registry but nothing calls `seedBoardFromFile` for the new
entry, which only runs at `listen`. Confirmed against a running server (201, then `count: 0` for
several seconds). Documented here as the caveat it is; making the registration seed its own board
is a behaviour change and belongs to an issue of its own.
